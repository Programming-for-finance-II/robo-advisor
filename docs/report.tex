\section{Introduction}
% ─────────────────────────────────────────────────────────────

Most commercial robo-advisors share three structural limitations: opaque models, undisclosed training data, and unconstrained AI components. This project addresses all three in an academic prototype combining a Gradient Boosting risk profiler trained on the Federal Reserve Survey of Consumer Finances (SCF~2022), a Hierarchical Risk Parity (HRP) portfolio optimizer with Ledoit--Wolf covariance shrinkage, and a constrained LLM narrator (large language model API) that is mathematically prevented from inventing figures via a Ground Truth JSON contract and a five-step validator. An EU Awareness layer (Rule~9) explicitly communicates the US-centric bias of the SCF training data to European investors at the point of recommendation.

The platform is a Streamlit web application backed by a FastAPI service, with a SQLite audit trail storing SHA-256 hashes of every market data snapshot and LLM prompt. An agentic GitHub Actions workflow demonstrates the mandatory AI agent criterion: a pull request generated entirely by the LLM API without human intervention.

Source code and Architecture Decision Records: \url{https://github.com/Programming-for-finance-II/robo-advisor}

\section{Backend and Data Infrastructure (P1)}
% ─────────────────────────────────────────────────────────────

\subsection{API Layer}
The backend is a \textbf{FastAPI} service exposing five endpoints: \texttt{/profile} (risk profiler), \texttt{/optimize} (portfolio optimiser), \texttt{/advice} (LLM narrator), \texttt{/backtest} (historical scenario analysis), and \texttt{/compare} (HRP vs.\ MVO side-by-side). All protected endpoints require an \texttt{X-API-Key} header validated on every request. Rate limiting is enforced via \texttt{slowapi} per IP address (20 requests per minute on \texttt{/profile}, 10 on the costlier \texttt{/advice}); requests exceeding the limit receive a \texttt{429 Too Many Requests} response without consuming any computation. All responses are Pydantic-validated, ensuring schema consistency between the backend and the Streamlit frontend.

\subsection{Data Pipeline: ValidatedDataLoader}
Market data is downloaded from \texttt{yfinance} by the \textbf{ValidatedDataLoader} (\texttt{backend/data/loader.py}). The loader applies three sequential quality controls before returning data to the optimiser:
\begin{enumerate}
  \item \textbf{UCITS probe.} For each primary UCITS ticker, a lightweight download is performed and the per-ticker NaN ratio is computed. If the ratio exceeds the 2\,\% threshold, the loader substitutes the corresponding US-listed fallback (e.g.\ \texttt{SPY} for \texttt{CSPX.L}) and records the substitution.
  \item \textbf{Forward-fill.} Gaps of up to two consecutive trading days are filled; remaining NaN values cause a \texttt{DataQualityError}.
  \item \textbf{Minimum observations gate.} At least 252 valid trading days (one calendar year) must remain after cleaning; shorter series are rejected.
\end{enumerate}
The cleaned price matrix is serialised to CSV and hashed (SHA-256) to produce the \texttt{market\_data\_hash} stored in the audit trail.

\subsection{Audit Trail}
The SQLite database (\texttt{robo\_advisor.db}) contains two tables. \texttt{market\_data\_snapshots} stores one row per unique \texttt{market\_data\_hash}, using \texttt{INSERT OR IGNORE} for deduplication: identical market data downloaded on different days produces a single stored snapshot. \texttt{recommendations} stores one row per optimisation request, linking to the corresponding snapshot via the hash and recording the full input parameters, profile output, portfolio weights, and risk metrics. This design enables bit-for-bit reproducibility of any historical recommendation from the stored hash alone. The application is containerised via \texttt{docker-compose.yml}; on Streamlit Community Cloud the database resets on redeploy, as documented in ADR-005.

\section{ML Risk Profiler (P3)}
% ─────────────────────────────────────────────────────────────

\subsection{Architecture}
The profiler operates in two phases. \textbf{Phase~A} is a rule-based fallback using the Grable--Lytton (1999) instrument \parencite{grable1999}: ten questionnaire items scored on $[0,30]$ are mapped to three profiles (\texttt{CONSERVATIVE}, \texttt{MODERATE}, \texttt{AGGRESSIVE}), with a capital-preservation override that caps the profile regardless of total score. \textbf{Phase~B} uses a trained GBM classifier grounded in empirically observed household behaviour. Both phases return a uniform \texttt{ProfilerOutput} typed dictionary, so downstream components are agnostic to which phase produced the classification.

\subsection{Label Construction and GBM Classifier}
Training labels are derived from the SCF~2022 \parencite{FedSCF2022} ($n=4{,}595$ households, implicate~1). Four allocation variables (\texttt{EQUITY}, \texttt{BOND}, \texttt{CASHLI}, \texttt{STOCKS}) are normalised and clustered via K-Means ($K=3$, silhouette $s=0.84$). Clusters are labelled deterministically by mean equity share. A \texttt{HistGradientBoostingClassifier} is trained on nine questionnaire-derived features with SCF sample weights preserved. \subsection{SHAP Explainability}
SHAP values are computed via \texttt{TreeExplainer} and normalised by absolute magnitude. The top-$N$ drivers are injected into the Ground Truth JSON; the LLM narrator is constrained to reference only features present in \texttt{top\_drivers} (Rule~7), preventing fabricated correlations.

\subsection{Hierarchical Risk Parity}
HRP \parencite{LopezdePrado2016} was selected over MVO for three structural reasons (ADR-001): it requires no matrix inversion, no expected-return estimate, and produces no corner solutions. The algorithm proceeds via Ward-linkage tree clustering on a Ledoit--Wolf distance matrix, quasi-diagonalisation, and recursive bisection assigning weights inversely proportional to intra-cluster variance:
\[
  \alpha_L = 1 - \frac{V_L}{V_L + V_R}, \qquad V_k = \mathbf{w}_k^\top \hat{\Sigma}_k\,\mathbf{w}_k
\]
Raw weights are tilted by risk profile: Conservative blends toward Minimum Variance; Aggressive toward Equal Risk Contribution \parencite{Maillard2010}; Balanced uses raw HRP weights.

\subsection{Ledoit--Wolf Shrinkage and Constraints}
The Ledoit--Wolf shrinkage estimator \parencite{LedoitWolf2004} $\hat{\Sigma} = (1-\alpha)S + \alpha\mu_S I$ is applied before clustering to stabilise the distance matrix. Box constraints clip weights to $[5\%, 40\%]$ per asset and $[10\%, 60\%]$ per cluster; weights are renormalised after clipping.

\subsection{Market Regime Detection}
A dual-trigger detector flags \texttt{HIGH\_STRESS} when $\bar{\rho}_{\mathrm{LW}} > 0.75$ or $\mathrm{VIX} > 30$ (ADR-006). Under stress, HRP is replaced by a cluster-level Equal Risk Contribution portfolio and a banner is shown in the frontend.

% ─────────────────────────────────────────────────────────────
\section{LLM Narrator and Validator (P4)}
% ─────────────────────────────────────────────────────────────

\subsection{Ground Truth JSON Contract}
All numerical computations are performed by the backend. The LLM receives a \texttt{GroundTruthPayload} containing pre-computed figures and is permitted only to narrate them. The payload includes portfolio weights, risk metrics (volatility, max drawdown, VaR, CVaR), profiler output with SHAP drivers, an \texttt{allowed\_numbers} whitelist (auto-populated by recursively extracting every float from the payload), and regulatory context. \texttt{expected\_annual\_return} and \texttt{sharpe\_ratio} are intentionally \texttt{null} for HRP, as the algorithm produces no reliable forward-return estimate.

\subsection{System Prompt: Nine Absolute Rules}
The narrator operates under nine rules enforced at prompt level: (1)~no invented numbers outside \texttt{allowed\_numbers}; (2)~no prescriptive advice (forbidden phrases injected from the payload); (3)~no compliance claims or absolutes; (4)~historical framing only for return figures; (5)~fixed out-of-context response; (6)~cluster descriptions in economic, not correlation, terms; (7)~SHAP drivers only; (8)~mandatory disclaimer; (9)~\textbf{EU Awareness} — when \texttt{profiler\_us\_centric\_caveat} is true, the narrator must acknowledge SCF US-centrism and European investor differences.

\subsection{Five-Step Validator}
Every response passes through \texttt{validator.py} before reaching the user. Steps 1, 2, 4, 5 are blocking; Step 3 is corrective:
\begin{enumerate}
  \item \textbf{Forbidden phrase check} — case-insensitive substring scan.
  \item \textbf{Hallucinated number check} — all floats extracted via regex, percentages normalised, checked against \texttt{allowed\_numbers} within $\pm2\%$ tolerance.
  \item \textbf{Disclaimer presence} — auto-appended if absent.
  \item \textbf{Injection detection} — semantic scan of output for known injection patterns.
  \item \textbf{EU Awareness (Rule~9)} — verifies SCF/Federal Reserve reference and European investor reference are both present when required.
\end{enumerate}

\subsection{Prompt Injection Defence}
Layer~1 sanitises user input before the API call: inputs exceeding 500 characters are rejected; known injection keywords are blocked case-insensitively. Accepted input is wrapped in \texttt{<user\_input>} tags. Layer~2 is Validator Step~4, catching cases where the model echoes injected instructions in its output.

\section{Limitations}
% ─────────────────────────────────────────────────────────────

\textbf{yfinance fragility.} The platform relies on an unofficial API with no SLA. UCITS-listed tickers occasionally return excessive NaN values; the \texttt{ValidatedDataLoader} mitigates this with automatic fallback, but live operation remains dependent on third-party data availability.

\textbf{SCF US-centrism.} The risk profiler is trained on US household data. European investors may exhibit materially different risk preferences, savings rates, and financial literacy patterns. The EU Awareness layer communicates this explicitly at the point of recommendation, but does not correct the underlying distributional mismatch.

\textbf{HRP opacity.} The recursive bisection algorithm produces weights that cannot be summarised by a simple rule. The LLM narrator and the MVO comparison tab partially mitigate this, but residual opacity is a fundamental limitation acknowledged in ADR-001.

\textbf{Validator false positives.} The substring check for \textit{safe} also matches the cluster label \textit{safe\_haven}, triggering unnecessary fallback responses. Whole-word matching is deferred to future work. The EU Awareness check (Step~5) is keyword-based rather than semantic and may fail on paraphrased compliant responses.

\textbf{SQLite persistence.} The audit trail resets on Streamlit Cloud redeploy. A managed PostgreSQL instance would be required in production (ADR-005).

\section{Conclusions}
% ─────────────────────────────────────────────────────────────

This paper presented an educational robo-advisor prototype demonstrating a complete investment workflow — from risk profiling to portfolio optimisation to natural-language explanation — while explicitly addressing transparency and geographic-awareness gaps common in commercial platforms. The Ground Truth JSON contract and the five-step validator represent the core architectural innovation: they make hallucination prevention structural rather than instructional. The EU Awareness layer (Rule~9, \texttt{profiler\_us\_centric\_caveat}, Validator Step~5) is a deliberate design choice to surface the geographic limitations of a US-trained model to European investors at the point of recommendation.

\subsection*{Future Work}
Replace the SCF~2022 training dataset with the ECB Household Finance and Consumption Survey (HFCS); replace \texttt{yfinance} with a reliable data provider; implement whole-word matching in the validator; add narrator retry logic before returning the safe fallback; extend the regime detector with a rolling confirmation window.
